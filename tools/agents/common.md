## Codebase orientation (read these first)
- `index.html` lists all scripts in load order; body scripts are `js/characters/<id>/logic.js` and `render.js` (see how `kiem_su`, `sprayer`, `customize` are included near the end of the characters block). Add yours there.
- `js/data/modules.js` — `MODULES.BODY` entries `{ id, name, desc, type:'body', size:{w,h}, stats:{hp,dmg,ammo,speedMult} }`. Append your body at the END of the BODY list. Also add a `role: [...]` field (primary role first; roles are 'Đối Đầu', 'Kiểm Soát', 'Cơ Động', 'Sinh Tồn') to your entry.
- `js/data/evolutions.js` — `EVOLUTIONS.<id> = [{id,name,desc,cost,type:'evo'}, ...]`.
- `js/core/hooks.js` — **CharHooks** (register per-body hooks: setup, update, speed, shoot, draw, drawUI, beforeDamage, shieldBreak, beforeLethal, damaged, roundEnd, shopButtons) and **BulletHooks** (per-bullet hit/edge/obstacle/draw), plus helpers `spawnBullet(owner, opts)`, `aimVelocity(sx,sy,target,speed,lead)`, `addStatusSlow(p,mult)`, `addStatusVuln(p,v)`, `zoneDist/zoneRectPath/zoneFit`, `laneTargetPoint`. Newer bodies (kiem_su, sprayer, customize, kiem_khach) are written entirely with these hooks — use them as templates (e.g. `js/characters/sprayer/logic.js` + `render.js`, `js/characters/kiem_su/*`, `js/characters/kiem_khach/*`). Read `js/player/combat.js` takeDamage to see how damage, shields, dodges (`options.unavoidable`, `options.isPiercing`, `options.bypassShield`) and the `beforeDamage` hook work; `js/player/bullets.js` for how bullets move/collide (bullets are plain objects in `owner.bullets` with x,y,w,h,vx,vy,dmg,owner,isPiercing,hitIds, optional `hook:'<name>'` to get BulletHooks callbacks).
- `js/entities/body-effects.js` — shared entity list `bodyEffects` (each entity has `update()`, `draw()`, `active`); updated by physics and drawn by render automatically. Classes `BodyZone`, `SkyStrike`, `HitscanTelegraph`, `StoneBlock` exist. `MortarMarker` (js/characters/aaa/summons.js) is the AAA artillery marker. `js/characters/tank/logic.js` has the TANK forward dash (charge up the field and come back).
- Crates: `crates` array (`Crate`, js/entities/world.js); to break one: `c.active=false; crateOnBreak(c, owner); grantCrateLoot(c, owner);`. Money trucks: `moneyTrucks` (`MoneyTruck`, hp). Summons/structures: `turrets`, `creatorTurrets`, `creatorDrones`, `creatorRobots`, `necroMinions`, `sniperWalls`, `bastions`, `ghostDecoys`; stones in bodyEffects have `isStone`. Damage players with `player.takeDamage(amount, attacker, options)`; stun with `enemy.freezeTimer = ticks`; bleed via `enemy.bleedTimer/bleedDmg`; slow via `addStatusSlow`.
- VFX: `explosions.push(new Explosion(x,y,radius,colorPrefix,dmg,owner))` (dmg 0 = visual only; colorPrefix like 'rgba(255,0,0,' or a CSS color), `addFloatingText(x,y,text,color,size)`, `spawnSparkParticles(x,y,color,count)`, `triggerScreenShake(intensity,duration)`, `soundSystem.playX()` (guard `soundSystem && !soundSystem.muted`).
- Gameplay is 1D: each tank only moves left/right on its own lane (P1 at the bottom, P2 at the top, rotated 180° for the P2 player). Bullets travel vertically between lanes; "forward" = toward the enemy (P1: negative y, P2: positive y). Canvas logical size is `canvas.width/height` (≈390×600-730 on phones).
- Input model: hooks get `inp` with booleans `inp.l, inp.r, inp.s` (s = shoot held). A `shoot(inp, now)` hook returning true fully owns the shoot button; detect press/release/hold durations yourself (store previous state on the player). While a body "takes over" left/right (e.g. steering a target circle) you can read `inp.l/inp.r` and use the `speed` hook to return 0 so the tank doesn't move.
- The on-screen shoot button for the local player: `document.querySelector('#p1-controls .btn-shoot')` for P1, `#p2-controls .btn-shoot` for P2 in local 2-player; in online mode the local player's controls are always `#p1-controls` (see js/player/update.js ~line 29 for the pattern). Only touch DOM from draw/drawUI-time or guarded code and never on the online host for the guest's player.
- **Online is host-authoritative**: the host serializes the world (players + global arrays) every tick and the guest only draws it. Keep ALL state in plain serializable fields on the player or on entities in `bodyEffects` (no functions/closures/Map/WeakMap in state). Every new class whose instances live in `bodyEffects` (or another synced array) MUST be added to `NET_CLASSES` in `js/online/netstate.js`. Use tick counters rather than Date.now() for timers.
- Smart bot: `js/ai/smart-bot.js` has `BOT_FIRE_STYLE` (per body: 'tap' default, 'hold:N' = hold N ticks then release, 'stream', 'toggle'). Add an entry for your body if 'tap' isn't right.
